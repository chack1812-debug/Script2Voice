# 台本への視覚描写埋め込み: @cast/@scene 自由記述拡張

## 背景・目的

`2026-07-02-video-production-pipeline-design.md`（4段階動画製作パイプライン設計）ではStage2（Claudeによるプロンプト生成）の入力を「台本.txt + characters_visual.json + scenes_visual.json」としていた。しかし台本と別ファイルでキャラ外見・場面情景を管理すると、台本を書き換えるたびに同期を取る手間と、両者がズレるリスクが生じる。

そこで、**キャラの外見・場面の情景描写を台本自体（`@cast`/`@scene`セクション）に自由記述で埋め込み、台本一本を読むだけでStage2のプロンプト生成に必要な情報が揃う**ようにする。これにより：

- 情報源が台本ひとつになり、再現性・保守性が上がる
- characters_visual.json / scenes_visual.json のサイドカーファイルとその同期の必要がなくなる
- Script2Voice本体（Rustパーサー）が対応するため、GUIプレビューや将来のバリデーション（未記述キャラの警告など）にも活用できる

## 現状の制約と技術的な鍵

`crates/s2v-core/src/parser.rs::parse_str` は行ループの先頭で

```rust
let line = line.trim();
if line.is_empty() { continue; }
```

としており、**空行はセクション判定より前に無条件でスキップ**される。このままでは「空行をキャストの区切りにする」仕様は実現できない。空行の扱いをセクションに応じて変える必要がある（後述）。

一方、`@scene`ヘッダー行の直後、次の`@pause`/`@asset`/`@cast`/`@script`が現れるまでの行は、現行実装では`match section { ... }`にマッチする腕がなく `_ => {}` で黙って捨てられている。つまりこの位置に自由記述を追加しても、既存の台本ファイルの解析結果は一切変わらない（後方互換に有利な空き地）。

## 解析仕様

### @cast セクション（状態機械化）

現在は1行=1キャスト定義として即座に`self.casts`へ格納しているが、以下の状態機械に変更する。

- セクション先頭、または直前の空行の直後にある最初の非空行 → **定義行**として現行ロジック（`役名:話者名:style,engine,params`、`splitn(3, ':')`）で解析し、「収集中のキャスト」として保持する。
- 収集中のキャストがある状態で、空行が来るまでの非空行 → すべて**自由記述（外見描写）**としてバッファへ追記する（順序を保って`\n`結合）。
- 空行 → バッファを結合して収集中キャストの`appearance`に格納し、状態をリセット（次の非空行を新しい定義行として扱う）。
- `@`で始まる行（次のセクションマーカー）が来た場合も、まずバッファをフラッシュ（末尾に空行を書き忘れても壊れないようにする）してからセクション遷移処理を行う。
- 定義行の解析に失敗する行（`splitn(3, ':')`で3要素に満たない）は、これまで通り無視する。ただし「収集中のキャストがない状態」でこれが起きた場合のみ定義行とみなして解析を試み、失敗時は何もしない（状態は「定義行待ち」のまま維持し、次の非空行を改めて定義行として試みる）。収集中のキャストがある状態の行は、内容によらず常に自由記述として扱う（コロンを含む描写文をキャスト定義と誤認しないため）。

### @scene セクション（本文蓄積）

- ヘッダー行（既存の音響パラメータ解析はそのまま変更しない）の後、次の`@`セクション行が来るまでの非空行を蓄積し、`\n`結合して現在のシーンの`description`に格納する。
- キャストと異なり1シーンにつき1つの記述ブロックしかないため、空行の特別な意味づけは不要（従来どおり読み飛ばす＝空行は見た目上の区切りとして扱われるだけ）。

## データ構造の変更

- `crates/s2v-core/src/cast.rs::Cast` に `pub appearance: Option<String>` を追加（`#[serde(default)]`）。
- `crates/s2v-core/src/types.rs::SceneConfig` に `pub description: Option<String>` を追加（`#[serde(default)]`）。
- どちらも追加のみで既存フィールドは変更しないため、既存のシリアライズ済みデータや既存コードとの後方互換性は保たれる。

## 後方互換性

- 空行の特別扱いは `@cast` セクションに限定するため、`@pause`/`@asset`/`@script` セクションでの空行の扱い（読み飛ばし）は変更しない。
- `@scene` ヘッダー直後の本文蓄積は、既存実装で黙って捨てられていた行を拾うだけなので、自由記述を書いていない既存の台本ファイルの解析結果（`Scene`/`Cast`の各フィールド値）は完全に同一になる。
- 既存の全17テスト（`parser.rs`内）はそのままパスする想定。壊れた場合は仕様の見落としとして修正する。

## 制約・注意点（台本仕様書に明記する）

1. **キャスト定義行の間に空行が必須になる。** これまで空行はレイアウト上の区切りに過ぎなかったが、この変更後は「2つのキャスト定義の間に空行がないと、2つ目の定義行が1つ目キャストの自由記述として飲み込まれる」という新しい制約が生まれる。`台本仕様.txt`のサンプルも更新する。
2. **自由記述の行は `@` で始めない。** 行頭`@`は無条件でセクション区切りとして扱われるため、描写文の行頭に`@`が来ると誤動作する（`@script`の台詞テキストにも元々ある制約と同じ）。
3. 定義行を書かずにいきなり自由記述だけを書いた場合、そのキャストは登録されない（既存の「定義行解析失敗時は無視する」という壊れ方をそのまま踏襲する）。

## Stage2（動画製作パイプライン）への影響

`2026-07-02-video-production-pipeline-design.md` のStage2入力を以下のように変更する：

- **変更前**: 台本.txt + characters_visual.json + scenes_visual.json → prompts.json
- **変更後**: 台本.txt（@cast/@sceneの自由記述込み）→ prompts.json

characters_visual.json / scenes_visual.json のサイドカーファイル方式は廃止する。Claude（Stage2）は台本.txtを直接読み、`@cast`の自由記述（`appearance`）と`@scene`の自由記述（`description`）をキャラ外見・場面情景の情報源として使う。

## テスト方針

`crates/s2v-core/src/parser.rs`のテストモジュールに以下を追加する：

- `@cast`定義行1つ＋自由記述複数行＋空行 → `appearance`が正しく結合される
- `@cast`に自由記述がないキャスト（空行のみ、または即次のセクション） → `appearance`が`None`のまま
- `@cast`で空行を挟まず2キャストを定義した場合 → 2つ目の定義行が1つ目の自由記述として飲み込まれる（意図した制約であることの確認）
- `@scene`ヘッダー後に複数行の自由記述 → `description`が正しく結合される
- `@scene`に自由記述がない場合 → `description`が`None`のまま
- 既存の`SIMPLE_SCRIPT`等、自由記述を含まない既存テストが全てパスすること（回帰確認）
