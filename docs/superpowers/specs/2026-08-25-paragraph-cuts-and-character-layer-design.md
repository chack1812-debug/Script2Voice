# 台本仕様変更（ルビ区切り・段落名）と動画2層合成 設計書

作成日: 2026-08-25

## 背景・目的

1. **ルビが振れない語がある**: ルビ記法 `'語:読み'` は語・読みに `:` を含められない（`parser.rs:349` の `'([^':：]+?)[:：]([^':：]+?)'`）。区切りを半角パイプに変更する。
2. **段落に意味がない**: `#paragraph` は引数を持たず、SRT には `[PARAGRAPH]` としか出ない。動画側は「段落の通し番号」でしか素材を指定できず、`scene_map.json` に同じパスを何十行も並べる運用になっている（実例: `三人寄れば・・・/20260822/scene_map.json` は実素材6枚に対し30以上のエントリ）。段落に名前を付け、名前で素材を解決する。
3. **絵の切り替えと人物の出入りは粒度が違う**: 現在の `compose` は「1セグメント＝1枚の静止画（または1本の動画）」で、キャラクターは背景に焼き込む前提。挿絵・動画カットは段落単位でよいが、キャラクターの表示は**話者単位**で切り替わるべきで、さらに**母音の口形状を当てた口パク**を行う。合成を**カット層**と**キャラクター層**の2層に分ける。

## 決定事項（2026-08-25、ユーザー確認済み）

| 論点 | 決定 |
|---|---|
| ルビ区切り | **半角パイプのみ**（全角 `｜` は区切りとして扱わない）。旧 `'語:読み'` は**廃止** |
| 役名区切り | **半角 `:` のみ**（全角 `：` のサポートを廃止） |
| SRT マーカー | `[PARAGRAPH 名称]`（大文字のまま。既存 SRT との互換を優先） |
| 素材の割り当て | `assets/<段落名>.<ext>` の自動検索 **＋** 名前入り `scene_map.json` 雛形生成コマンドの両方 |
| 同名連続段落 | 挿絵・動画カットは**1カットに結合**。キャラクター層は段落名を考慮せず**話者単位**で切り替える |
| 口パク | **母音ビセーム方式**。`closed / a / i / u / e / o`（任意で `n`）の口形状差分を用意し、母音タイミングに当てる |
| 旧台本の変換 | 使い捨てスクリプトで一括変換。**Script2Voice リポジトリには含めず、恒久保存もしない**（10章） |

## スコープ

**含む**: 台本仕様の変更、SRT/タイムライン出力の変更、`compose` の2層合成、口パク用モーラ情報の出力、CLI 追加、後方互換方針、旧台本の一括変換、ドキュメント・外部スキルの更新。

**含まない**: 素材（背景・立ち絵・口パーツ・詳細ボード）の生成そのもの、YouTube 投稿、GUI の新機能（既存動作の維持のみ）。

## 用語

- **段落マーカー**: 台本の `#paragraph [名称]`。
- **カット**: 挿絵・動画素材を1つ割り当てる時間区間。段落マーカーで区切り、**同名が連続する区間は1カットに結合**する。
- **キャラクター層**: カットの上に重ねる立ち絵レイヤ。話者単位で表示/非表示が切り替わり、口形状がフレーム単位で変わる。
- **モーラ**: 日本語の拍。VOICEVOX/AivisSpeech の `audio_query` が返す `accent_phrases[].moras[]` の1要素。母音と長さを持つ。

## 1. 台本仕様の変更

### 1.1 ルビ区切りを半角パイプにする（旧記法は廃止）

- 新記法: `'語|読み'`。**半角パイプのみ**。全角 `｜` は区切りとして扱わない。
- 新正規表現: `'([^'|]+?)\|([^'|]+?)'`
- 語・読みに `:` `：` を含められる（例: `'13:00|じゅうさんじ'`）。
- 旧記法 `'語:読み'` は**展開しない**。旧記法のまま残った台本は語も読みもそのまま読み上げられる（＝誤読として顕在化する）ため、移行は10章の一括変換で実施し、`check_ruby.py` で検証する。
- 台詞行の引用符内に全角 `｜` を見つけた場合は、区切り忘れの疑いとしてパース警告を出す（動作は変えない）。

### 1.2 役名区切りを半角 `:` のみにする

現状の `parser.rs:298` は「半角 `:` があれば半角、無ければ全角 `：`」という順で分割しており、**役名を全角 `：` で書いた行の台詞中に半角 `:` があると行が壊れる**。

```
蒼真：'13:00|じゅうさんじ' に始めます
→ 現状: 最初の半角 ':' で分割し、役名 "蒼真：'13" → 「キャスト未定義」で行が丸ごと無視される
```

ルビに `:` が解禁されると実害が出るため、**役名区切りは半角 `:` のみとし、全角 `：` の分岐を削除する**（`@cast` 定義行は元々半角のみ）。曖昧さが消え、判定順の問題も同時に解消する。

- 影響: 既存台本で役名に全角 `：` を使っている行（`D:\UDS\YouTube` 配下におよそ137行の候補）は「キャスト未定義」警告で無視される。10章の一括変換で半角へ直す。
- 警告メッセージを改善する: 未定義キャスト警告に「行頭が全角 `：` になっていないか」を示唆する一文を加え、移行中の事故を検知しやすくする。

### 1.3 `#paragraph` に名称を付ける

```
#paragraph                  … 従来どおり（無名）
#paragraph オープニング        … 名前あり
#paragraph scene03_koshien   … 名前あり（ファイル名向き）
```

- 書式: `#paragraph` の後に空白1つ以上、以降**行末まで**を名称とし、前後を trim する。名称は省略可。
- 名称に使える文字: 任意（空白・日本語可）。ただし
  - `]`・改行は不可（SRT マーカーの終端と衝突するため）。含む場合はパース警告を出し、**名称なし**として扱う。
  - Windows のファイル名禁止文字（`\` `/` `:` `*` `?` `"` `<` `>` パイプ）を含む場合はパース警告を出す（自動素材検索が必ず失敗するため）。名称自体は保持する。
- 型: `ScriptCommand::Paragraph(Option<String>)`、`TimelineProcessor::register_paragraph(name: Option<String>)`、`TimelineEvent` に `pub name: Option<String>` を追加。

### 1.4 `台本仕様.txt` の変更差分

- @script 節「単語と読みを":"で切り分ける」→ **「単語と読みを半角"|"で切り分ける」**、例示も差し替え。
- 役名区切りが**半角 `:` のみ**である旨を明記する（現在は暗黙に全角も通っていた）。
- コマンド一覧の `paragraph ****`（ユーザーが編集済み・未コミット）に、名称の用途（動画のカット名・素材ファイル名になる）と禁止文字の注意を追記。

## 2. 出力仕様

### 2.1 `timeline/subtitles.srt`

- 名前なし: `[PARAGRAPH]`（従来どおり）
- 名前あり: `[PARAGRAPH オープニング]`
- キーワードは**大文字 `PARAGRAPH` 固定**（既存 SRT・旧 Python 資料・`claude_code_instruction.md` と互換を保つ）。
- 0秒エントリである点は変更なし（焼き込んでも画面には出ない）。

### 2.2 `timeline/timeline.json`（新規・後段パイプラインの正式入力）

キャラクター層は「どの話者がいつ喋ったか」「発話ごとの音声ファイルはどれか」を必要とする。SRT からは復元できないため、**構造化タイムラインを新規に出力する**。`TimelineEvent` は既に `serde::Serialize` かつ `cast` を保持しているので追加コストは小さい。

```json
{
  "version": 1,
  "sample_rate": 48000,
  "total_ms": 899123.0,
  "events": [
    {"event_type":"audio","start_ms":0.0,"duration_ms":2450.0,
     "path":"audio/voice_0001.wav","mora_path":"audio/voice_0001.mora.json",
     "text":"…","display_text":"…","cast":"蒼真"},
    {"event_type":"paragraph","start_ms":2450.0,"duration_ms":0.0,
     "name":"opening","display_text":"[PARAGRAPH opening]"},
    {"event_type":"se","start_ms":3000.0,"duration_ms":0.0,"path":"…"}
  ]
}
```

- `path` / `mora_path` は project_dir からの相対パスに正規化する（プロジェクトごと移動できるようにする）。
- 一括実行のサフィックス（`_2` 等）は SRT/FCPXML と同じ規則で `timeline_2.json` とする。
- `compose` はこのファイルを優先入力とし、**存在しない旧プロジェクトでは従来どおり SRT の正規表現解析にフォールバック**する（その場合キャラクター層は使えない）。

### 2.3 `audio/voice_NNNN.mora.json`（新規・口パク用サイドカー）

3.5 参照。発話ごとにモーラ単位の母音と時刻を保存する。

### 2.4 `timeline/chapters.txt`（副産物・任意出力）

名前付き段落から YouTube 概要欄のタイムライン章立て（`0:00 オープニング` 形式）を生成する。現在は「SRT を人が読んで転換点を選ぶ」運用なので、名前付き段落の副次的な効果として自動化できる。無名段落しかない台本では出力しない。

## 3. 動画合成の2層モデル

### 3.1 全体像

```
timeline.json ─┬→ カット導出（段落名で結合） → 素材解決 → ffmpeg 入力群 ┐
               │                                                        ├ concat → [cut]
               └→ キャラ層タイムライン（話者単位の表示 ＋ 母音口形状）   │
                        ↑ audio/voice_NNNN.mora.json                    │
                        ↓                                               │
                  自前レンダラ（RGBA フレーム列） ──→ pipe:0 ───────────┴ overlay
                                                                          ↓
                          full_dialogue.wav ────────────────→ subtitles → libx264 → output.mp4
```

### 3.2 カット層

**カットの導出規則**

1. 段落マーカーを時刻順に並べる。
2. **時刻0のマーカー**（台本冒頭の `#paragraph 名前`）は境界を作らず、**先頭カットの名前**として扱う。※現在の `compute_segments` は `t <= prev` をエラーにするため、この例外を明示的に許可する。
3. 各セグメントの名前は「そのセグメントを開始させたマーカーの名前」。
4. **隣接するセグメントの名前が両方 `Some` かつ等しい場合、1カットに結合する**。`None`（無名）は結合しない。
5. 非隣接の同名（例: 段落1と段落40が同じ名前）は結合しない（別カットで同じ素材を使う）。

→ 無名だけの既存台本では規則4・5が発動せず、**従来と完全に同一のセグメント列**になる。

**結合の効果**: 20260822 の例で ffmpeg 入力が 30+ → 6 に減る。動画素材(mp4)がカットをまたいで頭出しし直されず連続再生される。反面カットが長くなるぶん「素材が短い」ケースが増えるため、`scene_map.json` エントリに任意の `"loop": true`（尺不足時に静止ではなくループ）を追加する。既定は現行どおり最終フレーム静止（tpad）。

**素材の解決順（カットごと）**

| 順 | 解決元 | 備考 |
|---|---|---|
| 1 | `scene_map.json` の `name` 一致エントリ | 明示指定。最優先 |
| 2 | `scene_map.json` の `index` 一致エントリ | 既存互換。index は**結合後**のカット番号（1始まり） |
| 3 | `<assets_dir>/<カット名>.<ext>` 自動検索 | `mp4, mov, webm, png, jpg, jpeg, webp` の順。既定 `<project>/assets`、サブフォルダを再帰探索。**複数一致はエラー**（曖昧さを黙って解決しない） |
| 4 | `scene_map.json` の `default_image` | 現行どおり静止画のみ |
| 5 | エラー | どのカットが未解決かを全件列挙してから失敗する |

`type` は拡張子から自動判定する（`type` の明示指定は引き続き優先）。

**`scene_map.json` の拡張（後方互換）**

```json
{
  "paragraphs": [
    {"name": "opening", "path": "assets/op.mp4", "loop": true},
    {"index": 3, "type": "image", "path": "assets/p03.png"},
    {"index": 4, "image": "assets/p04.png"}
  ],
  "default_image": "assets/default.png"
}
```

`name` と `index` は排他（両方あれば `name` を採用し警告）。旧形式はそのまま動く。

### 3.3 キャラクター層

**切り替え粒度は話者単位**（`timeline.json` の `audio` イベント）。カット名とは独立。

- 発話イベント `[start, start+duration]` の間、その `cast` を **speaking** とする。
- 表示規則は `characters.json` の cast ごとの `visibility` に従う:
  - `"always"`: 常時表示（例: 司会・技術者役）
  - `"speaking"`: 発話区間のみ表示。前後に `lead_ms` / `tail_ms`（既定 200/300ms）を付け、間隔がその和より短い連続発話は1区間に結合する（点滅防止）
  - `"never"`: 表示しない
- 同時発声（`#数字` による parallel）は audio イベントが重なるため、自然に複数話者が speaking になる。
- **カット単位の上書き**: 詳細ボード（全画面のコード・図解）のカットではキャラクターを隠したい。`characters.json` の `cuts` セクションでカット名ごとに `"characters": "hidden"`、または表示するキャストの配列を指定する。
- レイヤ順は `z` 昇順。

### 3.4 `characters.json`（新規・`compose` の任意入力）

口の差し替えは**パーツ方式（推奨）**と**全身差分方式**の両方に対応する。パーツ方式なら必要素材は「表情数 ＋ 口形状6枚」で済み、全身差分方式では「表情数 × 口形状数」の全身画像が要る。

```json
{
  "canvas": {"width": 1920, "height": 1080},
  "fps": 30,
  "casts": {
    "蒼真": {
      "visibility": "always",
      "z": 10,
      "anchor": {"x": 430, "y": 1080},
      "align": "bottom-center",
      "scale": 0.92,
      "default_pose": "default",
      "default_expression": "neutral",
      "poses": {
        "default": {
          "neutral": {
            "base": "characters/cutouts/souma_neutral.png",
            "mouth_origin": {"x": 262, "y": 180},
            "mouths": {
              "closed": "characters/mouths/souma_closed.png",
              "a": "characters/mouths/souma_a.png",
              "i": "characters/mouths/souma_i.png",
              "u": "characters/mouths/souma_u.png",
              "e": "characters/mouths/souma_e.png",
              "o": "characters/mouths/souma_o.png",
              "n": "characters/mouths/souma_n.png"
            }
          },
          "smile": {"base": "…", "mouth_origin": {"x": 262, "y": 180}, "mouths": {"closed": "…"}}
        }
      }
    },
    "大和": {"visibility": "speaking", "z": 20, "anchor": {"x": 1350, "y": 1080}, "…": "…"}
  },
  "cuts": {
    "board_tool_use": {"characters": "hidden"},
    "ending":         {"characters": ["蒼真"]}
  }
}
```

- パスは `characters.json` からの相対、または絶対。
- `base` を省略し `mouths` の各値に全身画像を書けば**全身差分方式**になる（`mouth_origin` も不要）。両方式を1ファイル内でキャストごとに混在させてよい。
- `mouth_origin` は `base` 画像内での口パーツ左上座標（スケール適用前のピクセル）。
- **口形状のフォールバック**: 未定義の母音は `a` → `closed` の順に代替する。`closed` のみ定義されていれば口は動かない（＝静止立ち絵として使える）。
- **このファイルが無ければキャラクター層は完全に無効**＝現行の合成と同一結果（既存回の再ビルドが壊れない）。

### 3.5 口パク（母音ビセーム方式）

**口形状**: `closed / a / i / u / e / o`（任意で `n`）。

**母音タイミングの取得（優先順）**

1. **VOICEVOX / AivisSpeech の `audio_query`**（本命）
   `http_engine.rs:157` で受け取り、cast params をマージして `/synthesis` にそのまま渡している `query` JSON は、`accent_phrases[].moras[]` に `text` / `consonant` / `consonant_length` / `vowel` / `vowel_length` を、句間に `pause_mora` を持つ。これに同 query の `speedScale` / `prePhonemeLength` / `postPhonemeLength` / `pauseLength` / `pauseLengthScale` を適用すれば、**モーラ単位の開始・終了時刻と母音が確定的に得られる**。synthesis に渡す直前の最終形なので、生成された音声と時間軸が一致する。
   → `HttpEngine::synthesize` を「query を捨てずにモーラ列を組み立ててサイドカーへ書く」よう拡張する。
2. **XTTS / 取得失敗時のフォールバック**
   合成テキスト（ルビ展開後）をカナ→母音列に変換し、発話長で等分割する。さらに RMS が閾値未満のフレームは `closed` に落とす。カナ化できない（漢字・英字が残る）場合は RMS の2値（`closed` / 既定母音 `a`）に退化する。

**サイドカー形式**: `audio/voice_NNNN.mora.json`

```json
{"version": 1, "source": "voicevox_query", "total_ms": 2450.0,
 "moras": [{"start_ms": 0.0,   "end_ms": 118.5, "vowel": "a",   "kana": "ア"},
           {"start_ms": 118.5, "end_ms": 210.0, "vowel": "i",   "kana": "シ"},
           {"start_ms": 210.0, "end_ms": 260.0, "vowel": "pau"}]}
```

- `vowel` は VOICEVOX 表記（`a/i/u/e/o/N/cl/pau`）。無声母音の大文字表記（`A/I/U/E/O`）は小文字に正規化する。
- `source` は `voicevox_query` / `kana_estimate` / `rms` のいずれか。フォールバック経路が使われたことを後から判別できるようにする。

**フレームへの割り当て**

- フレーム中心時刻を含むモーラの母音を採用する。モーラが1フレームより短くても一意に決まる。
- `pau` / `cl` と発話区間外は `closed`。`N` は `n`（未定義なら `closed`）。
- **平滑化は行わない**。母音タイミングが正確なので、ヒステリシスや最小保持フレームはむしろ遅延として現れる。パタつきが問題になった場合に限り、`characters.json` に `min_hold_frames`（既定0）を後付けする。
- 実装は純粋関数 `fn mouth_track(moras: &[Mora], speech: TimeRange, fps: u32) -> Vec<Mouth>` とし、単体テストで境界（モーラ跨ぎ、極小モーラ、`pau`、発話端）を検証する。

**時間軸の整合（実装時の必須確認）**: モーラ時刻は合成直後の raw 音声基準。`AudioProcessor`（定位・残響）が先頭に遅延を加える場合はその分オフセットする必要がある。P3 の着手時に `voice_NNNN_raw.wav` と `voice_NNNN.wav` の立ち上がりを比較し、オフセット量を確定してから実装する。

### 3.6 レンダリングパイプライン

**キャラクター層はフィルタグラフで組まず、自前レンダラ＋パイプで作る。**

理由: `overlay ... enable='between(t,a,b)'` を発話ごとに積むと15分の回で数百〜千のフィルタになり、フレーム単位の口パクでは完全に破綻する。自前レンダラなら filter_complex のサイズは発話数に依存せず一定。

```
ffmpeg -y -i full_dialogue.wav \
       <カット素材の入力群> \
       -f rawvideo -pix_fmt rgba -s <WxH> -r <fps> -i pipe:0 \
       -filter_complex "…scale/pad…concat=…[cut]; [cut][N:v]overlay=x=<X>:y=<Y>[v0]; [v0]subtitles=…[v]" \
       -map "[v]" -map 0:a -c:v libx264 -crf 18 … output.mp4
```

- レンダラは `image` クレートで RGBA 合成。素材（ベース立ち絵・口パーツ）は起動時に一度デコードし、`scale` 適用済みバッファをキャッシュする。
- フレームは「表示中キャスト × ポーズ × 表情 × 口形状」の組をキーにしてフレームバッファをキャッシュする。一意な状態は実運用で数十〜数百種なのでメモリコピーが支配的になる。
- **帯域対策**: キャラ層は全画面ではなく、全キャストの描画矩形を包含する**最小矩形**だけを流し、`overlay=x=…:y=…` で配置する（1920×1080×4×30fps ≒ 249MB/s を大きく下回れる）。矩形は `characters.json` から静的に計算できる。
- P2 の時点では口は `closed` 固定。パイプ構造は同じなので、P3 の追加は `mouth_track` の結線のみ。
- `fps` は `characters.json`（既定30）。FCPXML の fps 設定とは独立。

## 6. テスト方針（TDD）

- **parser**: 半角パイプルビ / 全角 `｜` は区切りにならない（警告のみ） / 語に `:` を含む / 旧 `:` ルビが展開**されない** / 全角 `：` の役名行が未定義キャスト警告になる / `#paragraph` 名前あり・なし・空白入り・`]` を含む（警告＋無名化）・ファイル名禁止文字（警告のみ）。
- **exporter**: SRT の `[PARAGRAPH 名称]` と `[PARAGRAPH]`、`timeline.json` のスキーマと相対パス化、一括実行サフィックス。
- **engines**: `audio_query` の JSON からモーラ列を組む変換（`speedScale`・pre/postPhonemeLength・`pause_mora`・無声母音の正規化）を純粋関数としてテスト。実エンジンは wiremock で固定 JSON を返す既存パターンを流用。
- **video/カット導出**: 無名のみ＝従来同一 / 同名連続の結合 / 時刻0マーカー / 非隣接同名は結合しない / 単調増加違反のエラー。
- **video/素材解決**: 解決順4段（name > index > 自動検索 > default）、拡張子優先順、複数一致エラー、未解決の全件列挙。
- **video/キャラ層**: 表示区間の生成（`always`/`speaking`/`never`、lead/tail、連続発話の結合、同時発声、カット別 hidden）、最小矩形の算出。
- **video/口パク**: `mouth_track`（モーラ跨ぎ、1フレーム未満のモーラ、`pau`/`cl`/`N`、発話端、未定義母音のフォールバック）。
- **回帰**: Python 版等価性テスト（無名台本・キャラ層なし）が引き続きバイト一致すること。

## 8. リスク・未決事項

1. **rawvideo パイプの帯域**: 理論最大 249MB/s。P2 の冒頭でベンチを取り、遅ければ (a) 最小矩形化の徹底、(b) ProRes4444 / VP9-alpha 中間ファイル経由、の順で対処する。
2. **モーラ時刻と処理後音声のズレ**: `AudioProcessor` が先頭に遅延を入れるか未確認。P3b の最初に実測してオフセットを確定する（3.5参照）。
3. **旧台本変換の取りこぼし**: 検証モード（旧展開＝新展開）で機械的に担保する。`D:\UDS\YouTube` は git 管理外なので、`.bak` を変換完了の確認まで消さない。
4. **ファイル名との暗黙結合**: 段落名の打ち間違いは「default_image に静かに落ちる」形で失敗しうる。`--dry-run` を制作フローの必須ステップとし、各番組の `CLAUDE.md` に手順として書く。
5. **キャラ層と焼き込み字幕の重なり**: `subtitles` は overlay の後に適用する。立ち絵の下端が字幕帯（画面下 150〜200px）と重なる問題は素材側の運用（AI道具箱で y=870px 制限の実績あり）で回避する。
6. **カット結合で素材の尺不足が増える**: `loop` オプションで緩和するが、既定は現行どおり最終フレーム静止。
7. **話者交代とカット切り替えの位相差**: 数フレームずれると不自然に見える可能性がある。P2 のベンチ時に実映像で確認し、必要ならカット境界へのスナップ（±100ms 程度）を入れる。
8. **口パーツの素材整備コスト**: パーツ方式でもキャスト3人 × 表情数 × 6口形状。P2 の時点では `closed` のみでも動くため、素材整備と実装を並行できる。
