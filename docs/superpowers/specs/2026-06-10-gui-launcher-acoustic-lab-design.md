# GUI（ランチャー＋音響ラボ）設計書

日付: 2026-06-10
Beads: s2v-6p2

## 背景・目的

Script2Voice は現在 CLI のみ。以下を目的に GUI を追加する。

1. コマンドラインを使わずに台本を選んで一括実行できる
2. **台本を書きながら、行単位で音響（定位・距離・部屋の響き）を試聴確認できる**
   — パラメータ設定中に音響のイメージがつかめない問題への対策
3. 音響演算（s2v-audio）を**台本なしで単独利用**できる入口を作る
   （任意 WAV への空間音響処理）

## 方式選定の経緯

- GUI スコープ5案（最小ランチャー／＋進捗ログ／音響チューニング特化／エディタ統合／
  ダッシュボード）から、エディタ統合＋音響ラボの方向を選択。
- 音響演算の単独利用案5件（ラボ画面／CLI サブコマンド／プリセット集／外部バインディング／
  リアルタイムプレビュー）のうち、**プリセット集＋ラボ画面**を採用。
  リアルタイムプレビューは「エフェクター化であり過剰装備」として**将来拡張**へ。
  外部バインディング（PyO3/DLL）も将来課題。
- エディタの持ち方3方式（egui 内蔵／Tauri 内蔵／**外部エディタ連携**）から**方式3: 外部
  エディタ連携**を選択。理由: 日本語 IME 品質問題を原理的に回避し、「保存→即試聴」の
  ループを最短工数で得る。エディタ統合は使い込んでから（使い勝手を研究してから）判断する。

## スコープ

### やること
- 新クレート `crates/s2v-gui`（バイナリ、egui/eframe）
- タブ1「台本」: ファイル選択・自動再解析・行リスト・書式チェック・行プレビュー・一括実行
- タブ2「音響ラボ」: プリセット＋パラメータスライダー＋任意 WAV 処理＋試聴履歴（A/B 比較）
- 音響プリセット `presets.toml`
- 既存ライブラリへの最小改修3点（後述）

### やらないこと（将来課題）
- 台本エディタの内蔵（外部エディタ＋ファイル監視で代替）
- リアルタイム・プレビュー（ストリーミング DSP 化が必要）
- 外部言語バインディング（PyO3 / C DLL）
- 壁素材のシーン単位指定（config.toml 全体共通のまま。プリセットにも含めない）
- 部分再生成・複数台本管理などのダッシュボード機能（画面の枠は拡張可能な構成にする）
- CLI `spatialize` サブコマンド（ラボ画面が同等機能を提供。必要になれば追加）

## アーキテクチャ

```
s2v-gui (egui/eframe, 単一exe)
 ├─ s2v-core    … 台本パース・Cast/SceneConfig（改修: 警告の構造化）
 ├─ s2v-engines … 行プレビュー用TTS合成（既存のまま）
 ├─ s2v-audio   … 音響演算（改修: バッファ入出力API公開）
 └─ script2voice lib … 一括実行（改修: 進捗イベント＋キャンセル）
```

- CLI `script2voice` は現状のまま共存。GUI は既存パイプラインの「別の入口」。
- 主要依存: `eframe`/`egui`（GUI。日本語**表示**のみで編集入力はしない）、
  `rfd`（Windows 標準ファイルダイアログ）、`rodio`（試聴再生）。
  台本ファイル監視は **mtime ポーリング（500ms）**で行う（notify は使わない。
  エディタの「一時ファイル→リネーム」型保存にも単純・確実に追従できるため）。
- TTS エンジンは行プレビュー初回に自動起動（既存 exe_path 機構）し、**GUI 終了まで
  起動を維持**（毎回の起動待ち回避）。終了時は既存の Job Object 機構で確実に停止。
- GUI 異常終了時もエンジンは Job Object（KILL_ON_JOB_CLOSE）で OS が回収する。

## 画面構成

ウィンドウ = 2タブ＋共通フッター（実行ログ。run.log と同内容をリアルタイム表示、折りたたみ可）。

### タブ1「台本」

- [台本を開く]（rfd ネイティブダイアログ）。前回のパスを記憶し起動時に復元。
- `notify` で監視し、保存のたびにデバウンス後、自動再解析（自動再読込 ON/OFF 切替可）。
- 行リスト: No／シーン名／キャスト／台詞先頭／[▶試聴]。
  パース警告（未定義キャスト等）はリスト内の該当位置に表示。
- 行プレビュー: 行クリック → その行の合成タスク1件を組み立て → TTS 合成（raw）→
  s2v-audio 処理（台本の @scene/@cast がそのまま適用）→ 一時 WAV → rodio 再生。
- 一括実行: [▶一括実行]［キャンセル］、進捗バー（Phase・n/全行）、
  完了後 [出力フォルダを開く][full_dialogue.wav を再生]。出力は CLI と完全に同一。
- 実行中・プレビュー中の二重起動は防止（ボタン無効化）。

### タブ2「音響ラボ」

- 音源: ●タブ1で選択中の行（合成結果を使用） ／ ○任意 WAV ファイル［選択...］
  （後者はエンジン不要 = 音響演算の単独利用）。
- プリセット選択（ドロップダウン）＋パラメータ:
  部屋 `room_w/d/h`、聴取 `listener_dx/dy/z`、`reverb_wet`、音源位置 `pan/distance/height`。
- [▶処理して試聴] → 処理結果を再生し**試聴履歴に追加**。
- [WAVに書き出し...] で任意の場所へ保存。
- `@scene` 行テキスト生成＋[コピー]（外部エディタに貼り付ける運用）。

#### 試聴履歴（A/B 比較）

- 1回の処理ごとに「通し番号・パラメータ一式・生成 WAV（一時フォルダ）」のペアを記録。
- 各行: [▶]（再処理なしで即再生）／[呼び戻す]（パラメータをスライダーへ復元）。
- 2件にチェックで [▶A][▶B] が有効になり、**再生成なしで交互に聴き比べ**。
- 上限 50 件（FIFO で自動削除）、[クリア] あり。GUI 終了で破棄
  （残したい音は [WAVに書き出し]）。

## プリセット（presets.toml）

- 配置: 実行ファイルと同じフォルダ（config.toml と同じ規約）。
- 内容は **@scene で表現できる範囲**＋ラボ用音源位置:

```toml
[[preset]]
name = "ラジオスタジオ"
room_w = 4.0
room_d = 5.0
room_h = 3.0
listener_dx = 0.0
listener_dy = 0.0
listener_z = 1.2
reverb_wet = 1.0
pan = 0.0        # ラボ用（@scene 行には含めない）
distance = 1.0   # 同上
height = 1.2     # 同上

[[preset]]
name = "2000席ホール"
room_w = 25.0
room_d = 45.0
room_h = 18.0
listener_dy = -15.0
listener_z = 1.1
reverb_wet = 1.0
# pan/distance/height 省略時は現在のスライダー値を維持
```

- 組込み既定プリセット（スタジオ／会議室／ホール／屋外風）をコードに内蔵し、
  presets.toml が無い/壊れている場合は組込みのみで継続＋警告表示。

## 既存ライブラリへの改修（最小・CLI の挙動は不変）

1. **script2voice lib**: 進捗イベント送信＋キャンセルフラグ付きの新関数
   `produce_with_events(scenes, events: Option<Sender<ProduceEvent>>, cancel: Option<Arc<AtomicBool>>)`。
   既存 `produce()` は従来挙動のまま（内部で新関数を呼ぶ）。
   イベント: Phase 開始、行完了 (n/total)、完了。
2. **script2voice lib**: `resolve_config_path` / `build_engine_manager` を main.rs から
   lib へ移設（GUI と CLI で設定解決・エンジン登録を共用するための純粋な移動リファクタ）。
3. **s2v-core**: パース警告の構造化（現状は warn! ログ＋該当行の暗黙破棄のみ）。
   未定義キャスト等を `ParseWarning`（行番号・内容）として `ScriptParser::warnings()` で
   取得できるようにする。GUI の書式チェック表示に使用。

（計画策定時の変更）当初挙げていた s2v-audio の `process_buffer` API は**追加しない**。
ラボ・行プレビューとも既存のパスベース `AudioProcessor::process()`（WAV読込→正規化→
リサンプル→DSP→書出し）で要件を満たすことが判明したため（YAGNI）。

## 対応エディタ・入力ファイルの前提

- **エディタは任意**（メモ帳・VS Code・サクラエディタ等、上書き保存できるもの）。
- 台本は **UTF-8 保存が前提**（パーサが UTF-8 読込）。**BOM 付き UTF-8 にも対応**
  （GUI 側で読込時に BOM を除去してからパーサへ渡す）。
- VS Code 等の「一時ファイル→リネーム」型の保存にも mtime ポーリングで追従。

## エラー処理

| 状況 | 挙動 |
|---|---|
| エンジン起動失敗 | タブ1にバナー表示。行プレビュー・一括実行を無効化（音響ラボの WAV 経路は使用可） |
| 非対応 WAV（非PCM等） | メッセージ表示して中断。多ch・サンプルレート相違は既存 `process()` の挙動どおり（Lch 使用・自動リサンプル） |
| presets.toml 破損 | 組込み既定プリセットで継続＋警告 |
| 実行中の操作 | 一括実行中は実行ボタン無効・キャンセルのみ可。プレビューの二重実行防止 |
| 台本の再解析失敗 | 直前の正常な解析結果を保持し、エラー内容を表示 |
| GUI 異常終了 | エンジンは Job Object で OS が自動回収 |

## テスト方針

- ロジックは GUI から分離してユニットテスト:
  プリセット読込（欠損キー・破損 toml）、`@scene` 行テキスト生成→`parse_scene_header`
  での往復一致、試聴履歴モデル（追加・上限 FIFO・A/B 選択）、
  モノラル化・サンプルレート変換、BOM 除去。
- ライブラリ改修3点は TDD。特に `process_buffer` は既存パス版との出力一致を検証。
- egui の画面表示そのものは手動スモーク（起動・タブ切替・一連の操作）で確認。

## 将来拡張の足がかり

- タブ構成のため、ダッシュボード（結果ブラウズ・部分再生成）や内蔵エディタは
  タブ追加で受け入れ可能。
- 内蔵エディタを検討する際は Tauri 移行も含めて再評価（音響・合成のコア呼び出しは
  本設計のライブラリ API をそのまま流用できる）。
